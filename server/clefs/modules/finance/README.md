# Finance (`finance`)

Owner P&L pulse (04 spec section 6). Owned by lane **P Finance**; only that lane edits this directory (plus `tests/modules/finance/`).

- Migrations `1000`-`1004` (range 1000-1049); tables start with `fin_`; signal and metric keys use `fin.`; jobs and permissions use `finance.`.
- Console routes live under `/hotels/{slug}/finance/` (`router.py`). OAuth for Xero, QuickBooks and Zoho runs through core: `GET /hotels/{slug}/oauth/{xero|qbo|zoho}/start` (permission `finance.connect`) and `/public/oauth/{provider}/callback`.
- `api.py` is the public surface (frozen signatures): `weekly_pulse`, `monthly_summary`, `verified_profit`.

## What it does

| Part | Files | Notes |
|---|---|---|
| Weekly pulse (no P&L) | `pulse.py`, `ports.py` | ARN and OccRN from `occupancy_daily`; rooms revenue from stayed `reservation_nights` (rate x rooms, plus SC only when `profit_guard.api.treat_sc_as_revenue`); Dist from `profit_guard.api.distribution_cost_by_night`; leakage from `cancellation_cost_by_date`; `service.api.recovery_cost`. NRevPAR = (RoomsRev - Dist) / ARN; OTA cost per occupied room = OTA cost / OccRN, with a per-channel breakdown. A missing input or a 0 denominator is `null` ("n/a"). Neighbour calls run in SAVEPOINTs and fall back to the stub defaults. |
| Imports | `imports.py`, `accounts.py` | Core ingest commit handler for `PL_STATEMENT` and `TRIAL_BALANCE`: one `fin_import_batches` row per month column, lines in `fin_pl_lines` (income positive, expenses negative; TB lines are credit - debit). The printed Net Profit line becomes `source_net_profit_minor`. Tally exports are recognised by their primary groups (`tally_upload`, upload-only). A re-upload of the same bytes rewrites its lines; a newer statement supersedes older unpublished ones. |
| Connectors | `connectors/` | Xero Reports (`/connections`, `Reports/ProfitAndLoss?fromDate&toDate&standardLayout=true`, `Reports/TrialBalance?date`, header `xero-tenant-id`, account ids from cell Attributes) and QuickBooks Reports (`/v3/company/{realmId}/reports/ProfitAndLoss?start_date&end_date&accounting_method=Accrual`, `reports/TrialBalance`). Hash of the canonical report JSON = batch sha256, so an unchanged re-sync is a no-op. Zoho is a stub (`NotConnected("coming next")`). Report parameters are UNVERIFIED (04 spec 7.7). |
| USALI taxonomy | `usali.py` | The closed 45-key table (`UsaliLine` Literal), the schedule, department, category and payroll flag per key; the DB CHECK in 1001 lists the same keys (tested). |
| Mapping | `mapping.py` | Rules (1.0) -> the hotel's own locked mapping for the same code + name -> global memory (exact name, 3+ hotels, 0.9, never fed by Xero data) -> LLM (`ai.structured`, task `finance.map_accounts`, `store=False`, batches of 60, few-shot only from this hotel's confirmed mappings). Every proposal needs a person: bulk "Confirm all >= 0.85"; anything lower one at a time. Confirmed = locked and reused every month; a renamed or regrouped account gets a new version (the previous line as a 0.8 proposal). The service-charge rule follows `treat_sc_as_revenue` (revenue: SC income -> `rooms.revenue`; pass-through: both sides -> `excluded.balance_sheet`). |
| Checks | `review.py` | 1 reconciliation (P&L: mapped net profit + the excluded.* sum = source net profit, so uncancelled pass-through such as Tourism Dirham collected vs remitted is a reconciling item, not a failure; TB: the source side already drops excluded.* lines; tolerance max(1 major unit, 0.01%); unmapped or unconfirmed accounts block), 2 PMS rooms revenue within 2% (warn; Profit Guard's per-(channel, currency) rows convert to the hotel's currency at the month end, and a row with no rate is left out and listed in `fin_stat_inputs.fx_skipped`, never summed raw), 3 OTA booked net (normalised view, GOP unchanged), 4 pass-through taxes excluded (block) and rooms/PMS in [1.20, 1.27] (warn), 5 below-GOP lexicon needs an `override_reason` (block), 6 TB debits = credits (block), 7 ratio bands and z-scores (warn), 8 revenue sign (non-positive TOR blocks). Status: `mapping_required` -> `checks_failed` / `review` -> `published` (-> `superseded`). |
| Summary | `summary.py`, `publish.py` | GOP = departmental profit (incl. misc income) - undistributed; margin = GOP / TOR; GOPPAR, TRevPAR, RevPAR per ARN; labour % = all payroll / TOR; EBITDA = GOP - mgmt fees - non-operating; net profit = EBITDA - below the line. Flow-through = dGOP / dTOR against the same month last year, else the prior month; n/a when abs(dTOR) < 1% of TOR. Publish snapshots `map_versions` and writes `fin_monthly_summary` (with per-line totals in `lines`). |
| Anomalies | `anomalies.py`, `signals.py`, `actions.py` | abs(z) >= 2.5 with a move >= 3 pp against the trailing 6 published months (labour %, EWW %, expense-line shares), else the bands (labour 20-45%, EWW 3-12%, configurable). Top 3 by abs(delta) x confidence -> `fin.anomaly` signals offering `finance.investigate_anomaly` (a human task; never counts toward verified profit). |
| Verified profit, market, baseline | `api.py`, `benchmarks.py` | Verified profit = sum of verified, counting action outcomes (reversals are already 0) bucketed by `verified_at` in hotel time, per available room. GOPPAR market chip: same-month YoY against admin-entered public benchmarks (YTD when the market figure is YTD); relative = (1 + hotel)/(1 + market) - 1, with the caveat. n/a when last year's GOPPAR (month or YTD) is <= 0: a change off a loss has no honest sign. The baseline (12 trailing published months + mapping snapshot) is immutable (trigger). No target, tier or milestone anywhere (tested). |

## Demo data (`demo.py`, 04 spec 7.4)

`seed_demo(cur, hotel_slug, rng, anchor)` imports one 13-month P&L CSV (2025-08 .. 2026-08, mixed EN/AR names) through core ingest, confirms the mapping, seeds `fin_stat_inputs` overrides for every month (2026-07: PMS 400,000, OTA share 70%, expected commission 44,100; 2026-08: PMS 424,100, ARN 2,480), publishes in order and registers the baseline. Only the planted findings fire: the labour anomaly in 2026-06 and booked net in 2026-07. Returns the plants for `expected_plants.json`. The demo CLI does not call module seeders yet.

## Jobs, signals, metrics

- Jobs: `finance.weekly_rollup` (Mon 05:00 hotel time, prior ISO week), `finance.stat_inputs` (day 2, 05:30), `finance.connector_sync` (day 3, 06:00), `finance.memory_rebuild` (Sun 03:30 UTC, platform-wide), tasks `finance.map_propose`, `finance.anomaly_scan`, `finance.register_baseline`.
- Signals: `fin.nrevpar_weekly` (money_available, weekly), `fin.pl_pulse_ready` (verified, monthly), `fin.mapping_needed` (service_risk, monthly), `fin.anomaly` (money_lost, monthly), `fin.booked_net` (compliance, monthly).
- Metrics (Ask): `fin.nrevpar`, `fin.ota_cost_por`, `fin.cancellation_leakage`, `fin.recovery_cost` (weekly, `finance.weekly.view`); `fin.gop`, `fin.gop_margin_pct`, `fin.goppar`, `fin.trevpar`, `fin.revpar_pl`, `fin.flow_through_pct`, `fin.labour_pct`, `fin.dept_profit` (dimension `department`), `fin.pl_line` (dimensions `usali_line`, `department`) from published months only (`finance.pl.view`); `fin.verified_profit` (dimension `module`), `fin.verified_profit_par` (`finance.view`). Money metrics use the hotel's currency.

## HTTP API (`/hotels/{slug}/finance/...`)

Money is `*_minor` (int) next to a Decimal string in major units (never floats); ratios are Decimal strings (`"0.3283"`) next to percent strings (`"32.83"`); `null` means n/a. Errors are `{detail, code}`.
