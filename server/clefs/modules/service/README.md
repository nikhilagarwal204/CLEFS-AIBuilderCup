# Service Control (`service`)

Owned by lane **A Service** from Wave 1. Only that lane edits this directory (plus `tests/modules/service/`).

- Migrations: `migrations/NNNN_service_<desc>.sql|.py`, numbers 0100-0199 (`python -m clefs.migrate new --module service "desc"`).
- New tables start with `svc_`. Legacy tables it owns (names grandfathered): `pending_requests`, `staff_members`, `staff_requests`, `staff_shifts`.
- Keys (jobs, metrics, signals, actions) start with `service.` or `ops.`; permissions with `service.`.
- `api.py` is the public surface; other modules import ONLY `clefs.modules.service.api` (signatures frozen, see `clefs/CONTRACTS.md`).
- `legacy.py` holds the pre-refactor routes; paths and JSON shapes are frozen by `tests/foundation/test_legacy_contract.py`.
- Need something from a frozen foundation file? Work around it locally and leave a `# FOUNDATION-REQUEST:` comment.

## Behaviour notes

- **States** `scheduled, new, assigned, acknowledged, in_progress, completed, cancelled, reopened`. The legacy `status` is derived in the same UPDATE (`new/scheduled -> new`, open -> `progress`, `completed/cancelled -> completed`); `accepted_at` is still written as the deprecated alias of `assigned_at`.
- **Legacy PATCH**: `completed` -> complete; `progress` + `assigned_to` -> assign by name then ack (a person typing their own name is an ack); `progress` alone -> routing assigns; `new` -> unassign. A closed request asked back to `progress`/`new` is reopened first. Unknown statuses change nothing.
- **Ack clock**: the first assignment keeps the clock counted from creation (or release / reopen); reassign, decline and handoff restart it (new ladder cycle).
- **Merge**: same room + request type open within `merge_window_min` (10) is appended to (`merged: true`); complaints, escalations, feedback, emergencies, security and food or drink orders (each is its own priced order) are never merged. Legacy doors never merge. `api.create_request` takes an optional `idempotency_key` for tool executors that need exact replay (see Module API); a merged keyed call leaves its key on the `merged` feed event (index `svc_request_events_merged_key_idx`, migration `0130`).
- **Rate limit**: guest sources, per room, `guest_room_limit` (5) per 10 minutes, counted in `staff_requests` -> 429 `rate_limited`. Staff sources are not limited; `/pending` keeps its own limiter and golden wording. Life safety is never refused: an `emergency` or `security` type, an L1 type default or hint, or an `emergency` sensitivity hint skips the count, and an over-limit request whose words hit the deterministic safety lexicons (no LLM) is let through flagged `over_rate_limit`. Placeholder rooms (`unknown`, `n/a`, ...) pool unrelated callers, so they are not counted as a room.
- **Translation**: non-English text through `clefs.ai.text("service.translate", timeout_s=2)`; ASCII text in a non-Latin language skips the call; a failure keeps the guest's words and sets `translated=false`, `flags.untranslated`.
- **Safety**: `api.classify_safety` (the classifier below), combined with the caller's hint and the request type, never downgraded. Emergency -> L1, sensitive/handoff -> at least L2; emergency and sensitive open an `svc_incidents` row and route on the urgent path.
- **Heat rule**: AC requests above `heat_threshold_c` (40) per `demand.api.outdoor_temp_c`, else June-September 11:00-17:00 hotel time, become high + L1. VIP tiers/tags and `returningGuest` are at least medium. Any L1 is high and raises `service.l1_incident`.
- **Routing pools**: `dept_floor`, `dept_device`, `dept_shared` (unoccupied department device; the first ack claims it), `supervisor`, `dept_legacy` (online department members), `fo_device`, `fo_online`, `fo_any`. Sensitive/L1 first try `duty_manager`, `security`, `security_device`, `gm`. Score `2*open_weighted + sla_pressure - idle(<=30) - 3*language - 2*continuity`, lowest wins; people at `max_open` are skipped while anyone is under it. Falling to Front Office (or nobody) raises `service.understaffed`.

## SLA timers and escalation (`sla.py`, `escalation.py`)

- **When**: `service.sla_sweep` every minute, and `sla.maybe_sweep(cur, slug)` on read when the last sweep is older than 30 s (in a savepoint, so a failure or a read-only transaction never breaks the read). `pg_try_advisory_xact_lock(hashtext('sla:' || slug))`: a second sweeper returns `{"skipped": "locked"}`. Rows another transaction holds are skipped for that minute (`FOR UPDATE SKIP LOCKED`).
- **Ack ladder** over v2 requests in `new, assigned, reopened` (pre-v2 rows, `intake_version IS NULL`, never escalate). Elapsed time counts from `ladder_started_at` (creation, release, reopen, or the last reassign/decline/handoff, which also bumps `ladder_cycle`). Levels are fixed by role: 0 assignee (local: the device repeats its chime, nothing is sent), 1 supervisor, 2 duty manager, 3 GM. Each step crossed inserts one `svc_escalations` row (UNIQUE per request, cycle, level: it fires once whoever sweeps), raises `escalation_level`, and writes an `escalated` feed event (`payload: {level, to, cycle, shadow, urgent, alarm: chime|loop, recipients}`). Past `ack_due_at` sets `sla_ack_breached` once and writes an `sla_breach` event (`action: ack`).
- **Urgent ladder** (sensitivity emergency/sensitive, or L1): the duty manager (level 2) at minute 0, plus Security (level 1) at minute 0 for the safety pathways only (an L1 AC failure does not page Security); the GM (level 3) at 0 for L1 or an emergency, else at 10. The Security step's feed event carries `department_key='security'` and no floor, so every Security device (and unscoped desk devices) loops its alarm. `sla.page_now(cur, slug, request_id)` runs these steps at once after intake; the sweep and `page_now` share the unique key, so a step is sent once.
- **Recipients** are resolved at the step from the roster: supervisor and duty manager are `svc_shift_assignments.shift_role` on shift now (a supervisor of the request's department first); without a roster, staff whose `role_key` names the role and who are online. Security: Security staff on shift or online. GM: active `gm` memberships (else `owner`), plus staff titled `gm`, deduped by phone.
- **Channels**: supervisor: none while on a live device session (the device alert), else WhatsApp, then SMS. Security and duty manager: WhatsApp, then SMS. GM: WhatsApp, SMS, then email. Staff WhatsApp needs `staff_members.whatsapp_opt_in`. Purpose `service.escalation`, platform sender, utility template `service_escalation_v1` (`{{1}}` hotel, `{{2}}` digest) outside the 24 h window.
- **Coalescing**: every step one sweep crosses for the same person becomes one digest (`"URGENT Hotel: 3 waiting: 701 EMERGENCY fire 1m, 504 Towels 6m, 612 Air conditioning 4m"`), idempotency key `svc.esc:{slug}:{person}:{minute}:{hash of escalation ids}`; each escalation row's `notify_ids` points at it. Messages never carry the guest's words; a sensitive case is only "sensitive matter".
- **Resolution**: past `resolve_due_at` (open states) sets `sla_resolve_breached` once, writes an `sla_breach` event (`action: resolve`) and adds "(overdue)" to the supervisor's digest (the duty manager's when no supervisor is on).
- **Shadow mode**: `escalation_mode` `auto` (default: shadow for `shadow_days`=7 after the hotel's first sweep, then live), `shadow` or `live`. In shadow everything is computed, stored (`svc_escalations.shadow = true`) and shown; nothing external is sent.
- **Bookkeeping**: `svc_sweep_state.last_sweep_at` / `last_result` (`{escalated, ack_breached, resolve_breached, sent, shadow, recipients, unreached}`); escalation rows get `acked_at` once the request leaves the unacked states or its cycle ends.

## Safety (`safety.py`)

- `classify(text, *, language, text_en, hotel_slug, use_llm, cur)` -> `{level: emergency|sensitive|handoff|none, kind, source: lexicon|llm|None, confidence}`; reached by other modules only through `api.classify_safety`.
- **Layer 1**, lexicons in 8 languages. Kinds and their fixed levels: emergency `medical, fire, sparks_flooding, violence, missing_child, death, lift_entrapment, drugs`; sensitive `harassment, theft, lost_document, police`; handoff `legal, chargeback, refund, complaint`. Guards are masked out before a kind's patterns run ("fire tv", "fire exit", "my phone died", "热死了", "mon vol", "l'avocat"). Word boundaries are script-aware (Devanagari vowel signs and Arabic diacritics count as letters); Arabic allows clitic prefixes; Chinese matches substrings. Lexicons read: the declared language, English, the English rendering (`text_en`), and every lexicon whose script appears in the text (Arabic script -> ar + ur, Devanagari -> hi, Cyrillic -> ru, CJK -> zh). German and French are read only when declared ("brand" is fire in German).
- **Layer 2**: `clefs.ai.structured("service.safety", timeout_s=1.5)` only when layer 1 found nothing urgent (none or handoff) and the hotel's `safety_llm` is on; it may raise the level at confidence >= 0.6, never lower it. AI off, a timeout or a bad answer keeps the lexicon verdict.
- **Effects** (`effects(verdict)`): emergency: skip AI resolution, incident, urgent route, page Security + duty manager + GM, L1, `ui` = the EmergencyCard. Sensitive: the same without the public card, GM only for L1. Handoff: a manager takes over, `promise_nothing`. `emergency_card(kind, security_extension=)` -> `{kind: "emergency", numbers: [the ones to lead with, e.g. 998, 999], directory: [{number, label, label_ar}] (999, 998, 997, 996, 995, 991), security_extension}`.

## Jobs, signals, metrics (`jobs.py`, `signals.py`, `metrics.py`)

- **Jobs** (per hotel): `service.sla_sweep` (1 min), `service.scheduled_release` (1 min: scheduled -> new, clock from release, routed), `service.session_autologout` (5 min: past planned end + `shift_grace_min`, or idle `idle_logout_min` on shared devices, meaning no `device_sessions.last_activity_at` touch and no action by that person on that device in the window; `end_reason` `auto_shift_end|auto_idle`. Nothing touches `last_activity_at` yet: the device routes should, on each staff interaction), `service.guest_confirm_expire` (hourly: unanswered 24 h after completion -> `unknown`; expired tracker tokens dropped after 30 days; raises `service.guest_unresolved` for the last two hours' answers), `service.repeat_fault_detect` (hourly, with reopen spikes), `service.daily_rollup` (00:30 hotel time: yesterday and the day before into `svc_daily_rollups`, hotel-local day bounds), `service.roster_labour_scan` (05:00 hotel time: next 7 days vs `svc_labour_rules` weekly/daily hours).
- **Signals**: `service.l1_incident`, `service.sla_breach_cluster` (any L1 past its ack time; 3+ breaches in the last 8 hours, one per business date and shift), `service.repeat_fault` (room + fault twice in 7 days; room type + fault 3 times in 14 days; auto-resolved when the pattern is gone), `service.reopen_spike` (3+ today and double the 14-day daily average), `service.guest_unresolved` (a "not resolved" from a VIP or on a second reopen), `service.understaffed`, `service.recovery_over_authority`, `service.labour_flag` (compliance), `service.l1_or_ack_breach` (the ACK ladder first reaching level 3, the GM: an L1 or safety request at once, anything else unacknowledged in time; one per request and ladder cycle, raised by `sla._escalate_row` in a savepoint only by the sweeper whose `svc_escalations` insert won; raised in shadow mode too, with a summary saying nobody was messaged; severity 4 urgent, else 3). `signals.raise_signal(cur, slug, kind, dedupe_key, title, ...)` is the helper other Service files use.
- **Metrics** (`service.view`): `service.requests`, `ack_p50_min`, `ack_p90_min` (v2 rows with an acknowledgement only; pre-v2 rows are left out), `resolve_p50_min` (completed only), `sla_ack_breach_rate`, `sla_resolve_breach_rate`, `reopen_rate`, `guest_confirmed_rate` (answers only), `requests_by_source`, `phone_desk_share` (percent 0-100), `recovery_cost_aed` (money, hotel currency, gestures given). Dimensions: `department, floor, shift, source, language, staff, room_type, stay_stage, request_type, severity`. Buckets are hotel-local days.
- **Wiring** (manifest and route owned by other parts): `module.py` must `import clefs.modules.service.jobs` (registers jobs, signal kinds and metrics); `GET /hotels/{slug}/service/queue` should call `sla.maybe_sweep(cur, slug)` before reading; intake should call `sla.page_now(cur, slug, row["id"])` (inside `state.guarded`) after opening an incident. Until then the sweep pages urgent requests within a minute.

This part adds no HTTP routes.

## HTTP API

All console paths are under `/hotels/{slug}/service/`. Errors are `{detail, code}`; a transition conflict adds `conflict: {request_id, state, version, by, at}`.

A **card** is the request as JSON: `id, room, type, subtype, description, category, priority, status, timestamp, assigned_to, accepted_at, resolved_at, state, version, source, language, original_text, translated, floor, room_type, stay_stage, location_slug, department_key, request_type_key, amenity_item_id, quantity, severity, sensitivity, sensitive_kind, assigned_staff_id, assigned_device_id, assigned_at, acknowledged_at, ack_implicit, started_at, cancelled_at, scheduled_for, ack_due_at, resolve_due_at, sla_policy_ref, sla_ack_breached, sla_resolve_breached, escalation_level, reopen_count, merged_count, guest_confirmation, guest_confirmed_at, shift_key, resolution_code, verified_room, incident_id, flags` (instants are epoch ms).

## Module API (`api.py`)

- `create_request(cur, hotel_slug, *, room, type, description, source, subtype=None, priority_hint=None, language=None, guest_ref=None, idempotency_key=None)` -> row + `tracking_token`, `merged`, `replayed`. `type` is a request-type key or a legacy type; `priority_hint` may be a severity `L1|L2|L3` (journeys). Guest sources may raise 429. `idempotency_key` (<= 200 chars, unique per hotel, namespace it by caller: `ups:order:812`, `cc:tool:<call_id>`) makes the call exactly replayable: the same key returns the first outcome's row with `replayed: true` whatever its state now, with no second card, rate-limit hit or appended words. A keyed first call may still merge into the room's open request; the key is then kept on the `merged` feed event and its replay returns that request with `merged: true`.
- `on_request_state(fn)` subscribes `fn(cur, change)` to every state machine transition (including routing's assignment right after intake; creation itself is not a transition). It runs inside the transition's transaction after the row, feed event and audit row are written, each subscriber in its own savepoint (a failing callback is logged and rolled back alone). A replayed device action notifies nobody. `change = {hotel_slug, request_id, action, from_state, to_state, status, version, actor_type, event_id, room, request_type_key, department_key, severity, source, guest_ref, amenity_item_id, quantity, resolution_code, assigned_staff_id}`, never the guest's words. Idempotent by identity; returns `fn`. Upsell registers at import to move an order when its linked request completes or is cancelled.
- `open_items_for_stay(cur, hotel_slug, *, room, since, until=None, reservation_id=None)` -> `[{id, request_type, severity, status, created_at}]` open (not `scheduled`) in `[since, until)`, oldest first. `reservation_id` widens it to the stay: the reservation's `room_number` (when `room` is `""`), requests filed with `guest_ref=str(reservation_id)` in any room (journeys file that way, so a room move is followed), and `checked_out_at` as the upper bound when `until` is None. No room and no known reservation -> `[]`.
- `escalate_to_human(...)` -> `{ok, request_id, assigned_to, tracking_token}`; sensitive excerpts never reach the description.
- `request_status_for_guest(cur, hotel_slug, token)` accepts the random token and the older signed form; `guest_view(row)` is the shared projection.
- `REQUEST_TYPE_FOR_DEPARTMENT` is keyed by the journeys' `department_hint` vocabulary (`housekeeping, engineering, ird, front_office, concierge, security, general`), with the legacy department names kept as aliases.
- `classify_safety(text, *, language=None, text_en=None, hotel_slug=None, use_llm=True, cur=None)` -> `{level, kind, source: lexicon|llm|None, confidence}` (see Safety). Never raises: a classifier fault falls back to the lexicons, then to `{"level": "none"}`. Callers read `none` as "the server adds no escalation", never as leave to drop one already raised. `SAFETY_LEVELS` is most severe first.

### Behaviour

- **Shift templates** are seeded per hotel on first read (UAE defaults: morning 07-15, evening 15-23, night 23-07, hk_day 08-17, hk_eve 15-24, with breaks), then owned by the hotel; never deleted, switched off with `active=false`.
- **Roster**: one row per person per business date. Template or explicit `HH:MM` times become TIMESTAMPTZ in the hotel's timezone; an end at or before the start is the next local day. `PUT roster` replaces the ISO week (Mon-Sun): rows left out are cancelled, not deleted. Instants come back in the hotel's offset (`+04:00`).
- **Labour guardrails** (guidance, not legal advice; `caption` on every response): weekly paid hours over 48, daily over 8 (Ramadan: 8 - 2 between `ramadan_start` and `ramadan_end`), a 7th day in a row (seen across week edges: a week either side is loaded as context), and the summer midday outdoor ban (outdoor roles, 12:30-15:00 local, 15 Jun - 15 Sep inclusive, half-open window; a night shift is checked on every date it touches). Paid hours = length - break. Only the midday ban blocks (`409 labour_blocked` with `flags`) unless the row carries `override_reason`, which is written to the audit log (`service.roster.labour_override`). Flags: `{code: weekly_hours|daily_hours|ramadan_hours|consecutive_days|midday_ban, level: warning|blocked|overridden, staff_member_id, business_date, message, refs, value, limit}`; `refs` echo the client's cell `key` (or `id:<n>`).
- **Handover** (computed on read, scoped to floors/departments): open and overdue requests, OOO/OOS rooms, open Engineering jobs, returning and VIP arrivals today (`guests.api.returning_arrivals`, masked for the viewer), incidents of the last 24 h (and any still open), lost-and-found stored in the last 72 h, notes of the last 24 h plus the `handover_note` left when a PIN shift ended. The acknowledgement stores counts and ids only (`svc_handover_acks`), stamps the notes' `acks` and the PIN session's `handover_ack_by/at`.
- **Staff SOS**: `kind=staff_sos, level=emergency, severity=L1`, floor from the person's roster assignment else the device. Pages Security and the duty manager on shift (WhatsApp with opt-in, else SMS; purpose `service.sos`) even in escalation shadow mode, raises `service.l1_incident`, publishes `service.incident`. Only a supervisor or duty-manager shift (or that job title) on the device, or a console `service.manage` user, closes or cancels it.
- **Recovery**: one open case per request. Authority roles: console membership via `MEMBERSHIP_AUTHORITY` (owner/gm -> gm, dept_head -> supervisor, front_desk/staff -> staff); device users by their shift role now, else `role_key`. Default matrix in minor units of the hotel currency: staff 100 {amenity, fnb_credit}; supervisor 300 + late_checkout; duty manager 1000 + room_night, upgrade, discount; GM unlimited (hotel rows in `svc_compensation_authority` override). Within authority: `given` now, ledger action `service.recovery_gesture` approved on the giver's authority (its executor marks it done). Above: `pending_approval`, `approver_role` = the lowest role above that covers it, ledger action owned by `APPROVER_OWNER_ROLE`, signal `service.recovery_over_authority`. The approver's own authority must cover the gesture (`403 above_authority`). A console `ignore` of the ledger action closes the gesture on read. Dial: default `suggest`; `auto_within_limits` takes `{max_amount_minor, once_per_stay}` and gives a system-proposed gesture (the tracker's "no" with `gesture_default_minor` set) at most once per stay per room.
- **Device outbox** (`POST /device/service/actions`): each item runs in its own savepoint and is idempotent on `client_event_id`; a closed request answers `conflict {request_id, state, version, by, at}` with code `already_closed` ("Already done by Amina"); an ack queued before the request went to someone else is refused (`reassigned`) when its `client_at` is more than 60 s old; `client_at` in the future is clamped to server time; events more than 120 s late are `late_sync`. Staff activity touches `device_sessions.last_activity_at`.
- **Tracker WhatsApp**: consent first (`whatsapp_updates`, the hotel's consent text version when published), the phone stored sealed and matched by `contact_hmac`, the utility template `request_status_v1` (`{{1}}` hotel, `{{2}}` request, `{{3}}` status; en/ar) sent at once and on each tracker state change (at most once a minute per subscription, never after consent is withdrawn).
- **WhatsApp fallback** (priority 90, guest, text): files a `source='whatsapp'` request idempotent on the message id; the room comes only from the sender's own tracker subscription in the last 7 days (never from the text); otherwise no room (Front Office). `STOP` reaching this slot ends tracker updates and withdraws the consent.
- **Analytics v2**: first response = ack - created, completion = resolved - created, work = resolved - ack; pre-v2 rows are counted (`pre_v2`) but left out of ack figures; a late-synced ack uses the device's `client_at`, never earlier than `assigned_at`; days are hotel-local.
